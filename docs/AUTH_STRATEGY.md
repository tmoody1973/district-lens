# DistrictLens Clerk Authentication Strategy

**Author:** Manus AI  
**Date:** May 07, 2026  
**Status:** Hackathon MVP architecture decision

## 1. Decision

DistrictLens should support **optional Clerk authentication** while keeping the core civic product **public-first**. A judge, voter, student, journalist, or civic researcher must be able to open the hosted demo, resolve a congressional district, view race and candidate information, inspect citations, and ask basic nonpartisan agent questions without creating an account.

Clerk should be used for personalization, saved workspaces, user preferences, saved briefs, and protected administrative operations. It should not become a required gate in front of the public civic-information experience.

> **Auth rule:** Clerk is optional for public civic exploration and required for saved user features, user-owned history, correction submissions, and admin-only import or refresh operations.

## 2. MVP scope

The MVP should treat authentication as a **P1/P2 layer**, not as the primary demo story. The highest-value hackathon path remains the MongoDB-backed race brief agent: resolve a district, retrieve bulk-imported FEC and Congress.gov/GPO records, inspect freshness, compare candidates, and produce cited answers.

| Capability | Auth requirement | MVP behavior |
|---|---|---|
| Landing page and district lookup | Public | No sign-in prompt before lookup. |
| Race dashboard | Public | Race pages are shareable and readable without an account. |
| Candidate comparison | Public | Finance, evidence, and incumbent context remain publicly readable. |
| Basic agent Q&A | Public with rate limits | The agent may answer without sign-in, subject to abuse controls. |
| Saved districts | Clerk required | Store the user’s saved districts by Clerk user ID. |
| Saved briefs and chat threads | Clerk required | Store user-owned artifacts in MongoDB only after sign-in. |
| Preferences | Clerk required | Save issue filters, preferred districts, and UI settings. |
| User-submitted corrections | Clerk preferred or required | Attribute submissions to a user and reduce spam. |
| Admin import and refresh endpoints | Clerk admin role or server-only secret required | Never expose bulk import, refresh, indexing, or extraction admin actions publicly. |

## 3. Data model implications

Clerk should be the identity provider, while MongoDB remains the application data store. DistrictLens should store only the minimum identity data needed to support product features. The canonical link is `clerk_user_id`, not email address.

| Collection | Purpose | Key fields |
|---|---|---|
| `user_profiles` | Store application-level user profile and role metadata. | `clerk_user_id`, `display_name`, `role`, `created_at`, `updated_at`, `last_seen_at`. |
| `saved_districts` | Let signed-in users bookmark districts or demo races. | `clerk_user_id`, `district_key`, `race_key`, `label`, `created_at`. |
| `saved_briefs` | Persist cited race briefs generated by the agent. | `clerk_user_id`, `brief_id`, `race_key`, `question`, `answer_snapshot`, `source_refs`, `created_at`. |
| `agent_threads` | Persist signed-in conversation history when enabled. | `clerk_user_id`, `thread_id`, `race_key`, `messages`, `created_at`, `updated_at`. |
| `user_corrections` | Capture correction or missing-evidence submissions. | `clerk_user_id`, `target_type`, `target_id`, `submission`, `status`, `reviewed_by`, `created_at`. |

DistrictLens should avoid storing raw residential addresses in user profile records. Address lookup caching should continue to use the configured district-lookup cache policy, preferably a normalized address hash or geocoding cache key, rather than attaching a raw home address to a Clerk user.

## 4. API access policy

The backend should separate **public civic read endpoints**, **signed-in personalization endpoints**, and **admin-only operational endpoints**. This keeps the judge-facing demo smooth while protecting data operations.

| Endpoint group | Access policy | Examples |
|---|---|---|
| Public read endpoints | Anonymous allowed | `/api/district/lookup`, `/api/races/{race_key}`, `/api/candidates/{candidate_id}`, `/api/races/{race_key}/finance`, `/api/agent/ask`. |
| User endpoints | Clerk user required | `/api/me`, `/api/me/saved-districts`, `/api/me/saved-briefs`, `/api/me/agent-threads`. |
| Correction endpoints | Clerk user preferred or required | `/api/corrections`. |
| Admin endpoints | Clerk admin role and/or server-only secret required | `/api/admin/import/*`, `/api/admin/refresh/*`, `/api/admin/sources/*`, `/api/admin/extract/*`, `/api/admin/index/*`. |

Public agent usage should still be rate-limited. If time is short, the MVP can make the agent public for judging and place stricter limits later, while keeping import and refresh administration protected from day one.

## 5. Demo guidance

The demo should not begin with login. It should begin with civic value. If Clerk is implemented, the sign-in moment should appear after the public workflow has already delivered value, such as “Save this district,” “Save this brief,” or “Keep this research thread.”

| Demo step | Recommended auth treatment |
|---|---|
| Open hosted app | Public landing page. |
| Choose a sample district | Public. |
| Ask DistrictLens for a cited race brief | Public. |
| Inspect FEC/Congress freshness and citations | Public. |
| Save the district or brief | Prompt optional Clerk sign-in. |
| Trigger bulk import or official refresh from admin UI | Admin-only, not part of public demo unless pre-authenticated. |

## 6. Implementation notes for Claude Code

Claude Code should implement Clerk only if it does not endanger the core demo path. If implemented, the frontend should use Clerk React components or middleware for optional sign-in, the backend should verify Clerk session claims on protected routes, and MongoDB records should map user-owned objects to `clerk_user_id`.

The public demo must keep working when Clerk keys are missing. In that case, saved-user features should be hidden or disabled, and the app should display a developer-facing configuration note rather than blocking civic read access.
